## 4. Module UI

* `GET modules` — فهرست پروژه‌ها + ماژول‌های فعال (eager-loaded: بدون N+1).
* `GET projects/{project}/modules` — صفحهٔ مدیریت ساختار: تعریف مجموعهٔ کامل (فقط وقتی ماژول فعال صفر است — سرویس)، بازتوازن وزن، ویرایش اطلاعات ماژول.
* `POST modules` → `ModuleService::createModules` (یک تراکنش، R-1) · `POST projects/{project}/modules/rebalance` → `ModuleService::rebalance` (R-2) · `POST modules/{module}/update` → `ModuleService::update` (وزن اینجا ممنوع: قاعدهٔ `prohibited` در FormRequest + rejection سرویس).
* **بدون delete/archive/restore UI** — هیچ قاعدهٔ تأییدشده‌ای برای حذف ماژول از Web وجود ندارد (DEC-038/039).

## 5. Stage UI

* `GET stages/{stage}` — وضعیت وزن (تخصیص/تأییدشده/باقی‌مانده)، حالت قفل، تاریخچهٔ کامل تأییدها با وضعیت هر رکورد، وظایف مرحله.
* مراحل از کاتالوگ نُه‌گانهٔ ثابت می‌آیند — **هیچ create/delete HTTP surface وجود ندارد**.

## 6. Stage Weight UI

* `POST modules/{module}/stages/rebalance` → `ModuleStageService::rebalance` (map جزئی؛ مجموع نهایی باید ۱۰۰ بماند).
* مراحل قفل‌شده (هر رکورد تأیید، pending هم قفل می‌کند — OQ-05=3A) در UI `disabled` و با 🔒 نشان داده می‌شوند؛ سرویس نیز مسیر را می‌بندد و پیام دامنه به flash error تبدیل می‌شود.

## 7. Approval UI

* `POST stages/{stage}/progress-approvals` → `propose()` یا `supersede()` (با `supersedes_approval_id`)
* `POST progress-approvals/{approval}/adjust` → `adjust()`
* `POST progress-approvals/{approval}/decide` → `approve()` / `reject()` (فقط supervisor در سطح route + سرویس)
* تمام قواعد (یک pending، سقف تجمعی، immutable، زنجیرهٔ supersede — T-1، مجوز mode-based، audit) در سرویس باقی‌مانده‌اند؛ کنترلر فقط exception دامنه را به flash error تبدیل می‌کند.

## 16. Security / authorization

* همهٔ ۱۸ مسیر جدید با `role:` middleware (همان الگوی موجود — TD-2 pre-existing) + گاردهای داخل سرویس‌ها (supervisor-only decide، mode-based propose).
* FormRequest اختصاصی برای هر مسیر تغییردهنده؛ `weight` در update ماژول `prohibited`؛ مبلغ/وزن با bounds سمت سرور.
* Route model binding + بررسی تعلق آیتم چک‌لیست به فاز (404) — بدون اعتماد به hidden fields.
* Isolation پیمکار: مسیرهای جدید برای `contractor` در سطح route ممنوع (403) و propose/decide در سرویس نیز گارد نقش دارند.
* CSRF: همهٔ تغییرات POST داخل گروه `auth` (web middleware).

## 17. Known limitations

* Authorization همچنان route-middleware محور است (بدون Policy class) — TD-2 قبلی، خارج از scope.
* `TaskController::create` هنوز امکان اتصال task به `module_stage_id` را در فرم ندارد — در Implementation Plan به‌عنوان «اختیاری طبق DEC-013» ثبت شده و در این اجرا انجام نشد تا دامنهٔ DEC-039 دقیقاً حفظ شود (فهرست بستهٔ §1 مأموریت Task edit را هم خارج از scope می‌داند).
* گزارش مرحله‌ای فیلتر تاریخ/دوره ندارد — در scope تأییدشده (DR-1) ذکر نشده بود.
