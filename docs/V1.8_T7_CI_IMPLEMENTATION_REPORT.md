## ۴. PostgreSQL Service Configuration

```yaml
image: postgres:18
POSTGRES_DB: tms_testing · POSTGRES_USER: tms_ci · POSTGRES_PASSWORD: tms_ci_password
health-cmd: pg_isready -U tms_ci -d tms_testing
```

- **UTF8/C locale:** image رسمی `postgres:18` به‌صورت پیش‌فرض با encoding `UTF8` و
  locale `C` initdb می‌شود (ENV-1 برآورده بدون flag اضافه).
- صفر SQLite · صفر MySQL · بدون fallback.

## ۵. Database Identity Safety Gate

**دو Gate، قبل از هر عملیات destructive:**

```text
Gate 1 (قبل از migrate):
  اتصال PDO مستقیم به همان env که Laravel استفاده می‌کند
  → SELECT current_database()  باید == tms_testing
  → SHOW server_version_num    major باید == 18
  → هر دو fail: exit(1) با پیام FATAL واضح

Gate 2 (بعد از migrate، قبل از tests):
  php artisan migrate:status
  → Pending == 0 و Ran == 32 (مجموعهٔ معتبر مخزن)
  → عدم تطابق: FAIL
```

Gate فریمورکی TestCase (T-6) نیز **به‌ازای هر تست** فعال می‌ماند — لایهٔ سوم.

## ۶. Migration Strategy

`php artisan migrate --force --no-interaction` — ساخت Schema از مجموعهٔ immutable
۳۲ مهاجرت، فقط روی `tms_testing` سرویس CI. Production `tms` کاملاً بیرون از محیط CI است.

## ۱۰. Security Considerations

- Credentialها **فقط** متعلق به سرویس CI (`tms_ci` / `tms_ci_password`) — هیچ
  credential واقعی تولید در workflow نیست؛ runner هرگز به `tms` دسترسی ندارد.
- **هیچ secret واقعی در لاگ چاپ نمی‌شود** — Gate 1 فقط `current_database` و major
  version را چاپ می‌کند.
- Artifact فقط `storage/logs/*.log` با `continue-on-error` — هیچ `.env`، APP_KEY یا
  config تولید upload نمی‌شود.
