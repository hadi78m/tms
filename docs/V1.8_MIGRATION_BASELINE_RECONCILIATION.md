## ۱۲. Rollback Strategy (Step 17)

| Migration | `down()` | ارزیابی |
|---|---|---|
| `M-07` | `throw new RuntimeException(...)` | 🔴 عمداً مسدود — طبق `DEC-018`. **در Batch مستقل است تا بقیه را متوقف نکند.** |
| `M-01` | `dropIfExists('modules')` | 🟠 مخرب برای دادهٔ ماژول (فقط روی محیط تازه بی‌خطر) |
| `M-02` | `dropIfExists('module_stages')` | 🟠 + `DROP TRIGGER` ضمنی |
| `M-03` | `dropIfExists('stage_progress_approvals')` | 🔴 از دست رفتن کل تاریخچهٔ تأیید |
| `M-04` | `dropIfExists('wbs_phase_checklist_items')` | 🟠 |
| `M-05` | `DROP CONSTRAINT`×2 → `dropIndex`×4 → `dropConstrainedForeignId`×2 → `dropColumn` | ✅ قابل بازگشت |
| `M-06` | `DROP CONSTRAINT`×3 → `dropIndex` → `dropConstrainedForeignId` → `dropColumn` | ✅ قابل بازگشت |
| `M-08` | `DROP TRIGGER`×4 **سپس** `DROP FUNCTION`×3 | ✅ ✅ ترتیب صحیح: Triggerها پیش از Functionها (وابستگی PostgreSQL) |
| `M-09` | حذف ردیف `progress_approval_mode` | 🟢 بی‌خطر |

**روش `down()` روی دادهٔ واقعی اجرا نشد** (فقط ترتیب SQL بازبینی شد). نکتهٔ کلیدی: `M-08.down()` در ترتیب معکوس **قبل از** `M-03.down()` اجرا می‌شود، پس Trigger روی `stage_progress_approvals` پیش از `DROP TABLE` برداشته می‌شود — وگرنه PostgreSQL خطا می‌داد.
