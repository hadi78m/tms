## Candidate A — Task ↔ Stage Assignment

* **Scope:** selector مرحله در Create Task (+ Edit اگر DR-2 اجازه دهد)؛ نوشتن `module_stage_id`+`module_id` در `TaskService::create` از خود Stage (الگوی DEC-021)؛ قاعدهٔ نقش DR-1؛ قید زمانی DR-2؛ رویداد audit `task_stage_assigned`.
* **Preconditions:** DEC-042 (DR-1) · DEC-043 (DR-2) ثبت شده باشند.
* **Required Owner Decisions:** DR-1 · DR-2 (+ در صورت تمایل، backfill/الزام stage — هر دو فعلاً «خیر» پیش‌فرض‌اند چون DEC-013/OQ-04=2B nullable را قفل کرده).
* **Affected:** `CreateTaskData` (+ فیلد اختیاری) · `StoreTaskRequest` (+ قاعدهٔ هم‌پروژگی: stage ∈ پروژهٔ تسک · `module_id` مشتق از stage، نه ورودی کاربر) · `TaskService::create` (+update در صورت DR-2) · `tasks/create.blade.php` (+edit) · `CreateTaskDataTest`/`TaskServiceTest` (سازگارسازی) · تست‌های جدید.
* **Models/Routes/Views:** Model: بدون تغییر (casts موجود) · Route: بدون تغییر · View: فرم تسک.
* **Database impact:** صفر · **Migration:** NO · **Audit impact:** یک رویداد جدید در همان تراکنش · **Authorization impact:** طبق DR-1 (route `role:` + گارد سرویس) · **Reporting impact:** DEC-040 دست‌نخورده (stageدارها وارد تجمیع می‌شوند؛ بی‌stage‌ها همچنان مجاز و شمرده).
* **Test Design (طرح — اجرا در فاز پیاده‌سازی):** create without stage · create with stage (مجاز) · unauthorized assignment هر نقش غیرمجاز · cross-project stage → رد · invalid stage id → 4xx · stage از ماژول/پروژهٔ دیگر → رد · change stage طبق DR-2 · change پس از حالت ممنوع → رد · audit row با old/new · old stage در audit · گزارش stage را منعکس کند · تسک بی‌stage همچنان مجاز + شمرده (DEC-040).
* **Rollback:** revert کد — هیچ state مخرب (صفر migration).
* **Acceptance criteria:** همهٔ تست‌های بالا سبز · suite کامل سبز · DEC-040/041 regression سبز · audit row در `activity_logs`.
* **Out of scope:** الزام stage · backfill · تغییر گزارش.
