# PART B — پاسخ صریح: آیا ساختار موجود از Assigned-based Scope پشتیبانی می‌کند؟

**خیر.** هیچ رابطه‌ای بین `users` و `projects` در مدل داده وجود ندارد؛ نه pivot، نه ستون مالکیت، نه جدول membership. تنها روابط «شبه-مالکیت» موجود:
* `projects.contractor_id` → شرکت پیمانکار (نه کاربر).
* `users.contractor_id` → شرکت پیمانکار (نه پروژه).
* `task_assignments` → assignment کاربر به **Task** (نه Project).

⇒ برای **Supervisor = Assigned-based** ساختار دادهٔ جدید **الزامی** است (Migration).

# PART I — دو درخواست تصمیم مالک

## DR-11-1 / ② — Supervisor Project Membership / Assignment Structure

**Evidence:** Part A/B/C/H — هیچ رابطهٔ Project↔User موجود نیست؛ تنها مورد ممکن Migration است.

**گزینه‌ها:** H-A (`project_user`) · H-B (`project_supervisors`) · H-C (`project_memberships` + role) · H-D (ستون روی `projects`) · H-E (نامعتبر).

**Tradeoffs:** H-A عمومی ولی بی‌نقش · H-B ساده ولی فقط supervisor · H-C انعطاف‌پذیر ولی پرحوزه · H-D ساده ولی بدون تاریخ و تک‌supervisor.

**Migration impact:** همه به‌جز H-E نیازمند جدول/ستون جدید. H-A/H-B/H-C ⇒ جدول pivot؛ H-D ⇒ ستون nullable روی `projects`.

**Test impact:** ماتریس supervisor×project (allowed/forbidden) · cross-project 403/404 · امکان چند supervisor (اگر گزینه اجازه دهد) · trusty تاریخ (اگر انتخاب شود).

**Unresolved questions:** multiple supervisors per project؟ start/end لازم است؟ دسترسی پس از پایان بلافاصله صفر شود؟ گزارش‌های تاریخی باید assignment قدیمی را نگه دارند؟ (Part C).

## DR-11-1 / ③ — Project Scope Enforcement Layer

**Evidence:** Part F (هیچ scope پروژه‌ای در هیچ لایه وجود ندارد؛ صفر Policy/Gate؛ الگوی غالب `role:` middleware + گارد دامنه).

**گزینه‌ها:** G-A (Policy-only) · G-B (Policy+Query Scope) · G-C (Middleware+Policy+Service) · G-D (Policy+Service Scope Guard) · G-E (FormRequest+Model Scope).

**Tradeoffs:** G-A ساده ولی نشت لیست · G-B دفاعی، نیازمند scope واحد مشترک · G-C قوی‌ترین، پیچیده‌ترین · G-D منطبق با دامنهٔ فعلی، ریسک فراموشی فراخوانی · G-E سبک، ضعیف.

**Migration impact:** همه G-* = **صفر Migration** (کد). Migration فقط در ② است.

**Test impact:** ماتریس Resource×Route×Role×Project؛ تست نشت فهرست (list leakage)؛ رگرسیون ۵۲ مسیر و contractor isolation.

**Unresolved questions:** آیا Audit (DEC-045) scope پروژه می‌گیرد یا system-wide می‌ماند؟ آیا گزارش‌ها (F-4 system-wide عمدی) scope می‌گیرند؟ آیا Management/Admin راست unrestricted شامل اقدامات نوشتنی است یا فقط خواندن؟
