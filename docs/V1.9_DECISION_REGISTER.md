## تصمیمات تأییدشده (Owner Resolutions — 2026-09-26)

### `DEC-039` — DR-1: V1.9 UI Scope = **Candidate A کامل**

- **تصمیم مالک:** Candidate A به‌طور کامل دامنهٔ V1.9 است.
- **دامنهٔ تأییدشده:** (1) Module CRUD · (2) مدیریت Stage · (3) مدیریت وزن Stage · (4) UI تأیید پیشرفت Stage · (5) UI WBS Checklist · (6) گزارش پیشرفت بر پایهٔ منبع معتبر `approved_amount`.
- **مقصود:** رساندن مدل دامنهٔ تأییدشدهٔ موجود به Web UI — نه افزودن قابلیت جدید دامنه.
- **مجاز نیست:** Performance Record/per-contractor · Support Ledger · Financing · محاسبهٔ مالی جدید · API شخص ثالث · sync jobs · AI · اپلیکیشن موبایل · webhook · حذف/بایگانی/بازگردانی Project · Refactoring نامرتبط · Candidate B · Candidate C.
- **Migration:** Candidate A انتظار می‌رود **صفر Migration** نیاز داشته باشد — این گزارهٔ scope/معماری است، **مجوز ساخت Migration در آینده نیست**.
- **تاریخ:** 2026-09-26

### `DEC-040` — DR-2: Tasks بدون `module_stage_id` در گزارش‌های stage-based = **Exclude**

- **تصمیم مالک:** در **گزارش‌های پیشرفت stage-based**، تسک‌هایی که `module_stage_id IS NULL` دارند **حذف می‌شوند** (معادل مفهومی: `WHERE module_stage_id IS NOT NULL` در لایهٔ تجمیع گزارش).
- **محدودهٔ مهم:** این تصمیم فقط دامنهٔ **گزارش stage-based** است و به این معنا **نیست**: حذف/ردِ آن تسک‌ها · منع ایجاد آن‌ها · تغییر رکورد DB · انتساب خودکار به Stage · حذف از سایر گزارش‌ها · قاعدهٔ جدید lifecycle.
- **ممنوع:** ساخت bucket جدید «تسک‌های نامرتبط» · قاعدهٔ وزن جدید برای تسک‌های بی‌stage · هر معنای کسب‌وکاری افزوده.
- **تاریخ:** 2026-09-26

### `DEC-041` — DR-4/OQ-07: برچسب گزارش «آماده پرداخت» → **«مبلغ تأییدشدهٔ مراحل»**

- **تصمیم مالک:** برچسب Legacy گزارش به «مبلغ تأییدشدهٔ مراحل» تغییر می‌کند.
- **شفاف‌سازی معنایی:** برچسب به `approved_amount` (مقدار تأییدشدهٔ مرحله — عملیاتی/درصدی وزنی، نه مبلغ مالی) اشاره دارد و به هیچ معنایی از «قابل پرداخت/محاسبهٔ پرداخت/فاکتور/تسویه/مجوز پرداخت پیمکار» اشاره ندارد. TMS عملیاتی باقی می‌ماند؛ محاسبات مالی در Contract System موجود است. V1.9 صرفاً به‌سبب تغییر برچسب هیچ محاسبهٔ مالی‌ای اضافه نمی‌کند.
- **تاریخ:** 2026-09-26
