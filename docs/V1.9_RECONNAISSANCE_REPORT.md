## ۶. Task Model

**Lifecycle واقعی** (از `TaskStateTransition.php` — نه حدس):

```text
draft → assigned → in_progress → submitted_for_review → under_review
      → supervisor_approved → approved (terminal)
 under_review/supervisor_approved → needs_rework → in_progress (چرخهٔ اصلاح)
 draft/assigned/in_progress/needs_rework → cancelled (terminal)
```

- Types: `TaskType = development | support` (`DEC-013/016/037`).
- Weight: ستون nullable legacy (M-07)؛ `DEC-034`: «Task هیچ Progress Weight مستقلی ندارد».
- روابط: assignments (multi)، dependencies (`DependencyType`)، documents (evidence)،
  approvals (technical/final)، SLA (response/resolution) — همگی با تست پوشش داده شده‌اند.

## ۷. Approval Model

- **Task Approval** (`ApprovalService`): `recordTechnicalApproval` (supervisor) ·
  `recordFinalApproval` (employer) · هر دو تراکنشی + audit؛ statuses از
  `ApprovalStatus`؛ `needs_rework` مسیر رد است (T-3 = مدل فعلی، `DEC-038`).
- **Stage Progress Approval** (`StageProgressApprovalService`): تجمعی/جزئی
  (`proposed_amount`/`approved_amount` — `DEC-034`) · supersede chain با گارد
  `assertNotSuperseded` (T-1) · immutable history · triggerهای DB
  (`assert_stage_weight_locked`, `assert_stage_approval_immutable`, `assert_history_not_deletable`).

## ۸. Weight / Progress Model

**نقشهٔ وابستگی واقعی:**

```text
Module Weight (SUM=100, تراکنشی) → Module Stage Weight (SUM=100, قفل پس از اولین تأیید)
  → StageProgressApproval (approved_amount تجمعی) → تنها منبع پیشرفت معتبر (DEC-034)
WBS Phase → Checklist (complete/incomplete — بدون weight محاسباتی)
Task weight → LEGACY/Deprecated (DEC-033) — اما ReportController هنوز می‌خواند ⚠️
WeightChangeRequest → LEGACY (صفر مصرف‌کنندهٔ فعال)
```

- Consumers فعلی weight: `ReportController` (گزارش) · `SettingController` · ۷ سرویس Domain.
- NULL possible: بله در Schema (M-07)؛ در مسیر HTTP ممنوع (`DEC-036`).
- **شکاف گزارش:** `ReportController:15-16` از `SUM(tasks.weight)` می‌خواند؛ منبع
  معتبر جدید (`SUM(approved_amount)` روی stage approvals) هیچ خواننده‌ای ندارد.

## ۹. Support Model

- `task_type='support'` رسمی (`DEC-016/037`) + مسیر UI Create Task.
- Support Stage = 15% هر Module (`DEC-005/034`) — در seed استاندارد stages موجود.
- `wbs_phase_id = null` مجاز برای support tasks.
- **صفر ledger اختصاصی support** — هیچ جدول/سرویس/گزارش اختصاصی وجود ندارد.
- SLA از `tasks.priority`/`SlaService` عمومی استفاده می‌کند (تفکیک support-specific صفر).
