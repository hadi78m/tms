## ۶. Concurrency Strategy

**دکترین قفل والد (`DEC-023`) — الزامی برای هر تراکنش تغییردهندهٔ یک محدودهٔ تجمیعی:**

| محدودهٔ تجمیع | والد قابل‌قفل | چه کسی قفل می‌گیرد |
|---|---|---|
| `SUM(modules.weight)` یک Project | **`projects.id`** | `ModuleService::createModules` · `rebalance` · `archive` · `restore` |
| `SUM(module_stages.weight)` یک Module | **`modules.id`** | `ModuleStageService` (تغییر وزن Stage پیش از قفل) |
| `SUM(active approved_amount)` یک Stage | **`module_stages.id`** | `StageProgressApprovalService` — **همهٔ** مسیرها: `propose` · `adjust` · `approve` · `reject` · `supersede` |

**الگوی الزامی:**

```text
BEGIN TRANSACTION
  → Lock Parent (SELECT … FOR UPDATE)
  → Read current rows of the aggregate scope
  → Apply changes
  → Validate invariant
  → Write + Audit
COMMIT
```

| قاعده | وضعیت |
|---|---|
| اتکای صرف به `Read Committed` / `Repeatable Read` | ⛔ **مجاز نیست** |
| Application-Level Check بدون Lock | ⛔ **مجاز نیست** |
| Source of Truth دوم / Snapshot غیرضروری | ⛔ **ممنوع** |
| `SERIALIZABLE` | 🟡 فقط گزینهٔ آیندهٔ Jobهای Import انبوه (با Retry) |
| الگوی موجود Repository | ✅ `WeightChangeRequestService:55-84` (`lockForUpdate()` + `DB::transaction`) — **الگوی جدیدی ساخته نشد** |

**هزینه:** تراکنش‌های نوشتنِ همزمان روی **یک پروژه/ماژول/Stage** سریال می‌شوند. حجم عملیات وزن‌دهی و تأیید کم‌ترافیک است → گلوگاه واقعی ایجاد نمی‌شود. هیچ قفل سراسری وجود ندارد.
